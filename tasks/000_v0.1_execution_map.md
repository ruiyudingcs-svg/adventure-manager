## 2. 当前阶段门

### Gate A：合同评分的数值映射

状态：已解决（2026-07-23）。权威规则见 `docs/15_staged_contract_resolution_rules.md` 第 4.1—4.3 节，并已同步到 `docs/02_core_loop_and_rules.md` 第 5、7 节与 `docs/04_data_model.md`。

- 四人快照的稀疏有向关系按六个无序成员对汇总，纪律读取四人平均值，任一方向不高于 -50 形成活跃冲突。
- `cohesion_modifier` 固定为 `clamp(round_away((cohesion_score - 50) / 5), -10, 10)`。
- 疲劳使用 0/1/3/5 四档逐成员相加；伤势使用逐成员 `ceil(injury_severity / 20)` 相加。
- `seeded_variance` 是闭区间 -10 至 +10 的离散均匀整数，每个 check 独立 RNG 恰好抽取一次。
- raw score 使用 64 位浮点，仅在等级判断前 `round_away` 一次，最终整数不裁剪并记录舍入原因。

Gate A 不再阻塞 Task 003。实现不得改变上述除数、阈值、分布或舍入顺序。

### Gate B：认可度与伤病结算

状态：已解决（2026-07-23）。Accepted 数值规则位于
`docs/15_staged_contract_resolution_rules.md` 第 5.1—5.5 节：

- 公开条款 success 价值影响按维度与合同意图做最强正/负覆盖；failure 影响不进入预测。
- 八种 trait 的 preferred/opposed method tag、0/1/2 禁忌强度和 `personal_fit` 六项分档固定。
- 五类补给具有固定 check、疲劳和伤病修正。
- 疲劳只在 final tier 后乘倍率并舍入一次。
- 伤病由 operational tier、check risk、当前疲劳、保护和补给汇总；每名成员独立 seed、一次投掷。
- 伤病先于条款，人员安全条款读取已生成的 heavy 数量；条款 cap 不回改或重投伤病。

Gate B 已在 Task 004 中实现并通过完整测试。Task 017 人工批准将单次 check 等级

## 5. 每个任务的统一执行规则

1. 开始前读取根目录 `AGENTS.md`、任务书列出的权威文档和现有测试。
2. 若权威文档缺少任务所需公式或彼此冲突，先报告阻塞；不得把猜测写成生产规则。
3. 只修改任务书允许的文件。需要扩大范围时先停止并说明原因。
4. 新规则必须有 focused test；确定性逻辑必须重复相同输入和 seed。
5. 先运行 focused tests，再运行完整命令：

```bash
godot --headless --path . --script res://tests/run_all.gd
```

6. 不自动更新 golden 期望；差异交给人工确认。
7. 完成后检查：范围膨胀、共享 Resource 被修改、UI 含公式、全局随机数、无原因状态变化。
8. 报告实际修改文件、行为、测试命令与结果、假设和剩余风险。未运行的测试不得声称通过。
