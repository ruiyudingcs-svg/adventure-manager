# Post-V0.1 Agency Roadmap

状态：Proposed planning，尚未成为 Accepted 实现规格
最后更新：2026-07-26

## 1. 背景

V0.1 已经证明了“阅读局势 → 选择合同 → 配置队伍 → 自动结算 → 承担后果 → 推进一周”的纵向流程可以运行。但试玩反馈显示，当前循环没有稳定形成玩家可控的管理体验：

- 组队界面缺少当前合同的直接参考，玩家需要在选人和任务评估之间来回跳转。
- 失败后财政、士气、人员可用性和世界局势容易连锁崩溃。
- 同定位角色受伤后，后续同技能需求合同缺少替代路径。
- 结算页的世界变化和原因日志更像系统审计，不够像玩家能理解的因果报告。
- 每周三份合同选择空间偏窄，玩家自然收缩到最高把握合同。
- 没有招募、临时补员和英雄定位成长，长期管理循环仍然不完整。

本路线的目标不是扩大 V0.1 范围，而是定义 V0.1 后的最小修正顺序。

## 2. 决策原则

1. 先提高可控性，再增加表现。
2. 失败应制造新压力和补救选择，不应一两次失败后让玩家只剩低风险本能。
3. 合同数量增加必须伴随难度分层，否则只是把“三选一最稳”变成“六选一最稳”。
4. 招募和补员先解决人员容量问题，再考虑更复杂的战斗或多队执行。
5. 新规则必须先写 Accepted 文档，再改代码和测试。

## 3. V0.1.1：Agency 与可读性修正

目标：不改变核心内容规模，先让玩家在当前循环里看得懂、选得动、失败后还能调整。

### 3.1 组队决策参考

Contract Planning 的选人区域应直接显示当前合同相关信息，不要求玩家跳转到单独评估视图再回来重选。

需要支持：

- 每名成员对当前合同的关键贡献标签，例如“侦察主力”“支援补强”“纪律稳定”“前线短板”。
- 加入或移除该成员后，预测 tier 区间、伤病风险和关键短板的变化摘要。
- 四阶段风险摘要，标出最危险阶段、主要缺口和最相关能力。
- 当前计划的队伍短板，例如缺前线、缺侦察、缺治疗、奥术不足、纪律不足。
- 成员态度、疲劳、伤势和拒绝风险在本合同中的直接影响。

UI 仍不得保存游戏公式。Presenter 可以调用领域查询或 forecast 服务生成只读 ViewData。

### 3.2 结算因果报告

Resolution 应从“日志列表”改为三层结构：

1. 顶部一句话总结本次成败原因。
2. 中部按成员、金币、阵营、世界局势分组展示后果。
3. 底部保留可展开的详细原因日志和调试级审计。

世界变化必须使用玩家语言解释，而不是只显示进度钟字段与数字。例如：

- “撤离进度 +10：队伍救出了一部分村民。”
- “聚落毁坏 +16：撤离失败导致东部村道失守。”
- “死灵污染 +5：尸体处理不及时，污染继续扩散。”

### 3.3 容错与压力调平

在改数值前先做可控性审计，记录人工策略下：

- 每周是否至少有两个可接受合同。
- 一次 Failure 后金币是否还能支撑至少两周基础维护。
- 一名关键定位成员重伤后是否仍有低效替代方案。
- Partial 是否能提供足够局势推进，避免非 Success 等同于无效。

允许的调平方向：

- 增加低难度合同或低收益保底结果。
- 降低早期重伤对战役的不可逆影响。
- 让 Partial 更常见，并让 Partial 可靠地产生部分目标收益。
- 增强失败后的解释和补救入口。

## 4. V0.1.2：合同组合与难度分层

目标：把合同选择从 3 选 1 扩展为更有结构的 6 选 1，同时不引入多队并行。

### 4.1 推荐默认形态：6 选 1

每个派系每周提供两个可见合同槽，总计六份候选合同。玩家每周仍只能接受一份主要合同。

每个派系的两个槽位建议固定职责：

| 槽位 | 职责 |
|---|---|
| 稳定槽 | 低难度、低收益、低世界影响，主要用于现金流、练新人和恢复节奏 |
| 压力槽 | 中高难度、高收益、强世界影响，主要用于推动结局方向或解决紧迫问题 |

这样玩家看到的不是“更多随机合同”，而是每个派系都在提供一个保守选项和一个战略选项。

### 4.2 6 选 2的处理

6 选 2 不建议作为 V0.1.2 默认规则。原因是当前只有一支四人队，若一周允许两个主要合同，需要新增容量模型、恢复模型或第二队执行，否则会加重伤病和财政压力。

可以保留为后续实验，但应满足至少一个前置条件：

- 已有临时补员或候选人系统。
- 第二个合同是轻量支援行动，不走完整四阶段主合同结算。
- 已定义“主合同 + 副合同”的不同后果强度、奖励和伤病风险。

### 4.3 难度分层

合同应显式声明玩家可见难度层：

| 难度 | 作用 |
|---|---|
| Routine | 稳现金、练新人、低伤病、低世界影响 |
| Standard | 默认主循环合同 |
| Dangerous | 高收益、高局势影响、失败代价明显 |
| Crisis | 阶段关键合同，不应频繁出现 |

难度不只是数值标签，必须影响：

- 预测解释。
- 推荐队伍要求。
- 奖励和失败代价。
- 是否适合新人或疲劳成员。
- 合同来源和派系槽位。

## 5. V0.2：招募、补员与英雄定位

目标：让长期人员管理闭环成立。

### 5.1 招募与临时补员

最小实现建议：

- 每两周出现 2 至 3 名候选人。
- 候选人有明确定位、工资、一个优势和一个短板。
- 正式招募增加工资压力。
- 临时帮手能力较低或只持续一周，但能补位并降低“同定位受伤即停摆”的问题。
- 候选池可受声望、阵营关系和近期结果影响。

V0.2 仍不需要永久离队、复杂雇佣谈判或完整员工部门。

### 5.2 英雄定位细分

三大职业原型继续保留，但每名英雄需要更明确的实际定位：

| 原型 | 可细分方向 |
|---|---|
| Vanguard | 守护、压制、撤离保护 |
| Ranger | 路线侦察、精确击杀、陷阱/风险预警 |
| Adept | 治疗、仪式、奥术控制、异常处理 |

同定位角色不应只是同一能力值高低，而应对应不同合同需求和风险类型。例：高侦察 Ranger 适合路线合同，高攻势 Ranger 适合猎杀合同。

## 6. 更后续：战斗表现

基础战斗可以增强表现，但不应优先于可控性修正。只有当合同选择、组队参考、结算因果、招募补员和难度分层已经能形成稳定管理循环后，才值得评估战斗表现。

推荐方向是“战斗摘要/阶段表现强化”，而不是让玩家直接操控战斗。直接操控战斗会削弱本项目的管理定位。

## 7. 下一批任务建议

建议拆成三个独立任务：

1. Task 018：Planning Agency Pass  
   增加组队参考、队伍短板摘要、成员贡献解释和预测变化提示。
2. Task 019：Resolution Readability Pass  
   重组结算页为因果报告，补齐世界变化的玩家语言解释。
3. Task 020：Contract Portfolio Spec  
   先写 6 选 1、难度层、派系双槽、候选生成和 UI 显示的 Accepted 规则，不直接改实现。

Task 020 通过后，再决定是否进入合同数量实现。招募与临时补员应作为 V0.2 的独立产品规格处理。
